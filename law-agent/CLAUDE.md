# CLAUDE.md — 일상 법률 문제 → 법령 기반 안내 에이전트

Claude Code에서 이어서 작업하기 위한 프로젝트 맥락 문서. (작성일 2026-11-06)

## 1. 목표
- 일반 사용자가 현실 문제를 입력하면 한국 법령·판례를 근거로 정보를 안내하는 에이전트 서비스.
- 핵심 난제는 검색이 아니라 **"일상어 → 법적 쟁점 변환"**. 단순 RAG가 아니라 단계형 에이전트로 구현한다.
- 프로토타입 분야: **주택임대차(전월세 보증금)**. 이후 근로 → 소비자 순으로 확장 (같은 구조 재사용).

## 2. 확정된 결정
| 항목 | 결정 | 이유 |
|---|---|---|
| 첫 분야 | 주택임대차 | 수요 큼, 법령 범위 좁음(주택임대차보호법·시행령·민법 임대차), 쟁점 유한, 행동 안내 명확, 평가 데이터 풍부 |
| 데이터 방식 | 수집·인덱싱(RAG) + 필요 시 API 도구 호출 | 응답 속도, 위임·참조 구조를 직접 설계 가능 |
| 원본 보관 | `data/raw`에 가공 없이 저장 | 청킹 방식을 바꿔도 API 재호출 불필요 |
| 인프라 | Azure | 아래 6절 |

## 3. 에이전트 처리 흐름 (6단계)
1. **사실관계 되묻기**: 결론이 갈리는 핵심 사실이 없으면 한 번에 2~3개만 질문 (계약서 유무, 계약 종료일, 전입신고·확정일자 등)
2. **쟁점 분류**: 분야·쟁점 (보증금 반환, 갱신요구, 묵시적 갱신, 대항력·우선변제권, 소액보증금 최우선변제, 임차권등기명령, 차임 증액 5% 제한)
3. **질의 변환**: 일상어 → 법령용어·관련 법령명 (예: "보증금 안 줌" → 임차권등기명령, 보증금반환청구)
4. **검색**: 조문 + 시행령 + 판례 + 법령해석례 + 생활법령 해설. 하이브리드(BM25+벡터), 위임·참조 조문 확장
5. **답변 생성** (고정 구조): 한 줄 결론 → 근거 조문·판례 → 지금 할 수 있는 조치 → 기한(시효 등, 눈에 띄게) → 상담기관(법률구조공단 132 등)
6. **인용 검증**: 답변에 인용된 조문번호·내용이 실제 조회 결과와 일치하는지 코드로 대조, 불일치 시 재생성 또는 인용 제거

## 4. 설계 원칙
- **청킹**: 법령 → 장 → 조 → 항 → 호 구조. 청크마다 법령명, 조문번호, 시행일, 소관부처 메타데이터
- **시점 처리**: 시행일·연혁 구분 저장 ("그 당시 법" 질문 대비). 답변에 기준일 표시
- **약칭 사전**: 개인정보보호법, 근기법 등 → 정식 명칭
- **불확실성**: 사실관계에 따라 갈리면 "A라면 ~, B라면 ~"로 분기, 단정 금지
- **근거 없으면 거절**: 조문을 못 찾으면 추측하지 않는다
- **에스컬레이션**: 소송 중·형사·고액 분쟁은 변호사·법률구조공단 안내
- **동기화**: 일 단위 증분 수집으로 개정 반영

## 5. 리스크 (출시 전 검토)
- **변호사법 제109조(비변호사의 법률사무 취급 금지)**: 개별 사건 법률 판단처럼 보이면 충돌 소지. "법령·판례 정보 제공"으로 포지셔닝하고 출시 전 법률 검토 필요
- **개인정보**: 사건 내용 입력 시 민감정보 포함 가능. 로그 보관 기간·마스킹·동의 절차 설계
- **환각 책임**: 틀린 조문·시효 안내는 사용자 피해 → 6단계 검증 필수
- **평가**: 법률구조공단·생활법령 실제 상담사례로 약 100문항 세트(`eval/`). 쟁점 분류율, 인용 조문 정확도, 되묻기 적절성, 행동 안내 적절성. 법률 전문가 샘플 검수 포함

## 6. Azure 구성 (확정 전 단계의 제안)
- **수집**: Azure Functions 또는 Container Apps Job, Blob Storage(ADLS Gen2), Key Vault, **NAT Gateway + 고정 공인 IP**
  - 법제처 API는 등록한 IP에서만 응답한다. Azure 기본 outbound IP는 바뀔 수 있으므로 Azure에서 수집을 돌릴 때는 고정 IP를 만들어 마이페이지에 추가 등록해야 한다
- **검색**: Azure AI Search (하이브리드 + 시맨틱 랭커), 메타데이터·참조 관계는 프로토타입에서는 인덱스 필드나 Blob JSON으로 시작, 규모가 커지면 Cosmos DB/Azure SQL
- **LLM**: Azure OpenAI (생성 모델 + 임베딩), Content Safety
- **호스팅**: Container Apps(API), Static Web Apps(UI). 공개 시 API Management
- **운영**: Application Insights, Managed Identity, 운영 단계 Private Endpoint
- **리전**: Korea Central 우선, 사용할 모델 배포 가능 여부 확인 필요
- **프로토타입 최소 구성**: Blob + Key Vault + AI Search(Basic) + Azure OpenAI 2개 + Container Apps 1개. 수집은 로컬 PC에서 하고 Blob에 업로드하면 NAT Gateway는 운영 단계로 미룰 수 있다

### 미검증 (다음에 가장 먼저 할 일)
- `scripts/collect.py`는 **문법 검사만 통과**했고 실제 API로 실행해 보지 않았다 (개발 환경 IP가 등록 IP와 달라서). 등록한 IP의 PC에서 아래를 실행해 확인한다.
  ```bash
  python -m venv .venv && .venv\Scripts\activate
  pip install -r requirements.txt
  python scripts/collect.py check
  python scripts/collect.py laws
  python scripts/collect.py prec --max 100
  python scripts/collect.py expc --max 30
  ```
- 응답 필드명(`법령명한글`, `법령일련번호`, `현행연혁코드`, `판례일련번호`, `법령해석례일련번호`)은 공식 가이드 기준으로 작성한 것이라 실제 응답과 다를 수 있다. 실패하면 `data/raw/*/_search/`의 응답 JSON을 보고 `find_items`와 필드명을 고친다.
- 신청 시 어떤 항목(목록/본문 형식)을 체크했는지에 따라 `미신청된 목록/본문` 오류가 날 수 있다. 스크립트는 JSON 목록 + XML 본문을 호출한다. 마이페이지에서 현행법령·판례·법령해석례의 목록 JSON, 본문 XML이 체크됐는지 확인한다.
- 권장했던 추가 항목: 법령용어, 지능형 법령정보지식베이스(일상어·법령용어-일상어 연계·관련법령), 법령 별표·서식, 국토교통부·법무부 법령해석. 현재 스크립트에는 이 항목들의 수집 코드가 없다.

## 10. 작업 규칙
- 사용자는 한국어로 소통한다. 답변·문서는 한국어로 작성한다.
- 인증키 등 비밀값은 코드·문서에 하드코딩하지 않고 `.env` / 운영 시 Key Vault를 쓴다.
- 원본(`data/raw`)은 수정하지 않는다. 가공 결과는 `data/processed`에 따로 쓴다.
- 법령 인용은 조회 결과와 대조해 검증한다.
